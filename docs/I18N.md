# i18n (localization)

The app ships two locales, Serbian (`sr`, default) and English (`en`), via `i18next` + `react-i18next`.
All user facing copy lives in JSON namespaces under `app/src/i18n/locales/<lang>/`.

## Structure

- `app/src/i18n/config.ts` is the single source of truth for languages and namespaces.
  - `LANGUAGES = ['sr', 'en']`, default is detected from `localStorage['runcast.lang']` then
    `navigator.language`; `sr` wins otherwise.
  - `NAMESPACES` lists every registered namespace. Each namespace must exist as
    `locales/sr/<namespace>.json` and `locales/en/<namespace>.json`, and imports for both locales
    must be added to the `resources` object in the same file.
  - `fallbackLng` is `sr`. Dates and numbers go through `Intl` with the locale from
    `localeForLanguage` (`sr-Latn-RS`, `en-GB`).
- Components read copy with `useTranslation('<namespace>')` or `useTranslation()` (default `common`).
  Cross namespace keys use the `t('workout:actions.skip')` form.
- `app/src/lib/use-page-title.ts` keeps `document.title` localized per route.
- Shared generated content (explanations, coach notes, fueling, race day, guided cues) is returned
  as `LocalizedText` keys from `packages/shared` and rendered with `t(key, params)`.

## Parity check

`scripts/check-i18n.mjs` (plain Node, no dependencies) compares `sr` and `en` and enforces
namespace registration. It reports:

- missing keys in either direction (this includes extra keys on the other side),
- keys present in only one locale,
- empty string values,
- placeholder mismatches (`{{count}}`, `{{from, number}}`, and so on),
- key type mismatches (string vs object vs array),
- namespaces registered in `config.ts` without files, and files on disk that are not registered.

Run it from the repo root:

```bash
npm run check:i18n
```

The script prints a namespace table plus a problem table and exits 1 when anything is off. The
`checks` job in `.github/workflows/ci.yml` runs it before typecheck.

## Copy rules

- `sr` is the primary locale. Write it first, then mirror meaning into `en`; never change meaning
  when fixing wording.
- Informal address (`ti`/`tvoj`), verbs in imperative for buttons and actions: `Sačuvaj`, `Izvezi`,
  `Uvezi`, `Pokušaj ponovo`.
- No em dashes (`—`) or en dashes (`–`) anywhere in locale values. Use `-` for numeric ranges
  (`RPE 3-4`, `06-09 h`) or words (`5 do 10 minuta`).
- Sentence case for section labels and headings (`Nedeljni kilometri`, `Ciljna trka`), Title Case
  only for proper nouns and acronyms (`GPS`, `HRV`, `ACSM` style abbreviations).
- Terminology is fixed: `trening` for a session, `trčanje` for the act, `dugi trk` (never `long`),
  `plan` for the training plan, `ciljna trka` for the goal race, `patike` for shoes,
  `Uvezi`/`Uvezeno` for health import (`Import`/`Imported` in `en`), `spremnost` for readiness,
  `u zatvorenom` for indoor.
- Keep placeholders (`{{...}}`) untouched and identical across locales, including their format
  options when present.
- Serbian uses a decimal comma (`0,4%`), English a decimal point (`0.4%`).

## Adding a namespace

1. Create `app/src/i18n/locales/sr/<name>.json` and `app/src/i18n/locales/en/<name>.json` with the
   same key structure.
2. Import both files in `app/src/i18n/config.ts`, add them to the `en` and `sr` entries of
   `resources`, and add `'<name>'` to `NAMESPACES`.
3. Use `useTranslation('<name>')` where needed.
4. Run `npm run check:i18n` and the i18n E2E spec (`app/e2e/i18n.spec.ts`) to confirm there are no
   raw keys after a language switch.

# 03 — UI / design-system audit

Scope: `app/src/styles/theme.css`, `app/src/components/{ui,layout,weather,workouts,forms}`, `app/src/lib/field-id.ts`, `app/eslint.config.js`.
Baseline: Apple fluid-interface principles + API consistency + contrast/token correctness. Read-only audit; fixes below are proposals.

## Summary

**Good**

- Token system is coherent and actually wired: every `--color-*` in `@theme` resolves (`bg-primary-soft`, `text-text-muted`, `border-border`, `divide-border`, `ring-primary/60` all valid in Tailwind v4).
- Typed, focused primitives; `clsx` used consistently; `className` pass-through works in AppButton/AppCard/AppBadge/AppModal/SegmentedControl/Skeleton.
- Field ids via `field-id.ts` are slugified (`Visina (cm)` → `visina-cm`), unique with current labels, and avoid duplicate-id footguns.
- Inter Variable import is correct (`@fontsource-variable/inter` → `'Inter Variable'`, `--font-sans` consumed by `font-sans`).
- Modal already becomes a bottom-anchored full-width sheet under `sm:` and Escape/scroll-lock are handled.

**Risky**

- **No press feedback at all**: zero `:active` styles in the repo; `primary-pressed` exists only as a hover color, so on touch nothing fires on pointer-down. This is the single most visible gap vs. the fluid spec.
- **No motion library** (`motion`/`framer-motion` absent from `package.json`) and no `prefers-reduced-motion` / `prefers-contrast` / `prefers-reduced-transparency` support anywhere; `animate-pulse`/`animate-spin` run unconditionally.
- **Contrast failures in the palette as used**: `text-muted` fails 4.5:1 everywhere (incl. `placeholder`), CountdownCard's text-on-orange is ~2:1, and `AppButton` primary (white-ish on orange) is ~2.4:1.
- **Keyboard/a11y gaps**: no `:focus-visible` on buttons/links/toggles (inputs use `focus:`, which also shows on click), no `aria-pressed` on SegmentedControl, no focus trap/focus restore in AppModal.
- **Duplication**: LogWorkoutModal re-implements AppInput's exact input styling + label markup by hand; WeatherSummaryCard re-implements AppCard; PaceZoneBadge re-implements AppBadge.

### Motion decision (blocks several fixes)

`motion` is **not a dependency**. Two paths:

1. **CSS-only now (recommended for P0/P1)**: `:active` scale + `transition-transform duration-100` covers press feedback with zero deps; reduced-motion handled in `theme.css`.
2. **Adopt `motion` for the sheet/tab polish (P2)**: `npm i motion` (React 19 supported). Springs per spec, damping 1.0 (bounce 0): press `{ type: 'spring', stiffness: 400, damping: 40 }`; sheet settle `{ type: 'spring', stiffness: 300, damping: 35 }` (ratio ≈1.0); drag-dismiss threshold `dismiss = offset > 0.4 * height || velocity > 500`, snap-back `{ type: 'spring', stiffness: 500, damping: 45 }` (ratio ≈1.0); momentum projection `dragMomentum` + `dragElastic={0.4}` (rubber-band at bounds); tab pill `layoutId` with `{ type: 'spring', stiffness: 500, damping: 45 }`. Only after momentum/drag gestures may bounce rise (`bounce` 0.1–0.2).

## Ordered implementation checklist

1. **Theme + global reduced motion** — darken `--color-text-muted`, add tracking tokens, add reduced-motion/transparency/contrast blocks. _Accept: computed ratio ≥4.5:1 for muted on `surface-elevated`; spinning/pulse animations stop under `prefers-reduced-motion`._
2. **Press + focus for all controls** — `:active` scale/colors on AppButton, SegmentedControl, NavLink, back button, refresh; `focus-visible` rings. _Accept: pressing any button visibly changes within one frame on pointer-down; keyboard Tab shows a ring, mouse click does not._
3. **AppInput/AppSelect/AppTextarea polish** — `focus-visible`, select chevron, placeholder token. _Accept: no focus ring on click; select has visible affordance._
4. **AppModal a11y** — focus trap, initial focus, restore, `aria-labelledby`, close button, blurred overlay. _Accept: Tab cannot leave modal; Escape/close return focus to trigger._
5. **SegmentedControl semantics** — `aria-pressed`, arrow keys, press feedback. _Accept: screen reader announces selected state; left/right arrows change selection._
6. **Kill duplication** — LogWorkoutModal → AppInput; WeatherSummaryCard → AppCard; PaceZoneBadge → AppBadge; tone maps consolidated; EmptyState/AppBadge extend `ComponentProps`. _Accept: no hand-rolled input classes remain; single tone→class map._
7. **Contrast fixes** — CountdownCard gradient/token; AppButton primary text; audit all `text-muted` placements. _Accept: every body-text pair ≥4.5:1 (large text ≥3:1)._
8. **Materials + tracking pass** — TabLayout translucent blur+saturation, edge fades, safe-area; display-size negative tracking. _Accept: content visibly scrolls under header/nav with soft edge fade; no 1px border under sticky bars._
9. **New primitives** — ProgressRing → StatsPage/Today weekly widget; Toast; ConfirmDialog; IconButton. _Accept: ring animates and respects reduced-motion; toasts announced via `aria-live`._
10. **Motion (optional, if adopted)** — drag-dismiss sheet, projection, rubber-band, tab pill per spring table above. _Accept: sheet dismisses by drag or velocity, snaps back under threshold, keyboard path still works._
11. **Lint** — run `npm run lint`; add `jsx-a11y` only if agreed. _Accept: lint clean._

## Out of scope

- Light theme / color-scheme switching, rebrand, icon set changes.
- Route-level code splitting, data-layer/API changes, new pages.
- Motion adoption itself is a dependency decision — the file proposes values but does not mandate installing the package.
- Membership/finance domain concepts (not present in this app).

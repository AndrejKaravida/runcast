# 05b — Pages pregled B (Stats, Settings, Onboarding, auth, 404)

Obim: `StatsPage`, `SettingsPage`, `OnboardingPage`, `LoginPage`, `RegisterPage`, `ForgotPasswordPage`, `ResetPasswordPage`, `NotFoundPage` (+ `features/plans/progress.ts` za math).

## Šta je dobro

- Auth stranice su uniformne i čiste: `zodResolver`, `noValidate`, `autoComplete` na svim poljima, server greške odvojene od validacionih, `AppInput` labela vezana preko `htmlFor`.
- Onboarding je pravi wizard: per-step validacija sa specifičnim porukama, live VDOT/paces preview iz `vdotFromPerformance`/`pacesFromVdot`, i poštena feasibility procena (3% prag) — bez lažnog optimizma.
- `willUseBasePlan` u onboarding-u se poklapa sa stvarnom logikom generatora (`plan-generator.ts:474`: `anchor === null || weeks < 12`) — upozorenje na koraku 5 nije kozmetika.
- `ResetPasswordPage` ispravno razlikuje `loading` / „nema sesije" / formu; `NotFoundPage` ima 404 bez lažnog CTA-a.
- Stats koristi `progress.ts` helpere (`weeklyKmSeries`, `adherencePct`, `runStreak`, `loggedKm`) umesto ručnog računanja, uz `EmptyState` za „nema plana".

### Konsolidacija onboarding ↔ settings (duplikat plan forme)

- Duplirano bukvalno: `DAY_KEYS` (2×1), `REFRESH_OPTIONS` (2×8), `tryParseTime` (2×7), `buildPlanInput` vs `handleGenerate` (2×~30), race/recent/days/longRun/experience blokovi (2×~60 redova JSX) + iste `t('days.*')`/`days` sekcije u oba namespace-a.
- Procena: ~120–140 linija + 2 seta validacionih pravila koja su već divergirala (format ciljnog vremena).
- Predlog (najmanji diff): `features/plans/form.ts` → `planFormFromPlan(plan, profile)` + `validatePlanDraft(draft, {requireRaceDate})` + `buildPlanInput(draft, {hasRace})`; `components/plans/PlanFields.tsx` → polja (datum, distanca, cilj, ref. trka, dani, dugi trk, iskustvo, volumen) sa `hasRace` prop-om. Onboarding korak 0–3 i Settings „Novi plan" tada dele isti render i ista pravila.

### Organizacija Settings sekcija

Trenutno: Jezik → Izgled → Profil → Trening → Plan → Nalog. Uzdrmano je jer: (a) Profil i Trening dele jedno nesnimljeno stanje i dva save dugmeta, (b) Plan drži i pregled i formu za generisanje, (c) Jezik/Izgled su „app" preference bez veze sa nalogom. Predlog: **Profil** (ime, grad, telesni podaci) · **Trening** (runWindow + refresh + fueling + nedeljni volumen) sa jednim Sačuvaj · **Plan** (pregled + export + „Novi plan" u `ConfirmDialog`/sheet umesto inline forme) · **Nalog** (email, promena lozinke, odjava) · **Aplikacija** (Jezik + Izgled). Time nestaje P0 jer svaka sekcija ima svoj save scope.

## Top 5 prioriteta

1. **P0 — Settings deli jedno stanje za Profil i Trening** (`SettingsPage.tsx:93-104`): izmene se tiho gube ili čuvaju pogrešnim dugmetom. Razdvojiti save scope (vidi predlog sekcija) pre daljeg rasta.
2. **P1 — Konsolidacija plan forme onboarding ↔ settings** (`~130` linija duplikata + divergentna validacija formata vremena): jedan `PlanFields` + `validatePlanDraft` + `parseOptionalTime`, čime se P1 „1:45:00" bug rešava na jednom mestu.
3. **P1 — Onboarding nije atomičan** (`OnboardingPage.tsx:216-235`): plan uspe, profil padne → petlja i duplikat plana; prvo profil, pa RPC, uz odvojene poruke.
4. **P1 — PlanForm ne može da menja volumen/iskustvo** (`SettingsPage.tsx:47-57,106-119`): regeneracija tiho nasleđuje stare vrednosti; dodati kontrole i upis u profil.
5. **P2 — Stats math rubovi**: streak 0 dok danas nije DONE (`progress.ts:32-43`), `doneKm` bez donje granice plana (`StatsPage.tsx:75-76`) i hardkodovan `dd.mm.` (`StatsPage.tsx:22`) — mali, izolovani popravci sa velikim efektom poverenja u brojeve.
